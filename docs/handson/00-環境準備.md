## 📝 環境変数の設定

### 方法の選択

環境変数の設定方法は、セキュリティと利便性のバランスで選択してください：

| 方法 | セキュリティ | 利便性 | 推奨シーン |
|------|------------|--------|----------|
| **Azure Key Vault** | ⭐⭐⭐⭐⭐ | ⭐⭐⭐⭐ | **本番環境・チーム開発（最推奨）** |
| セッション単位 | ⭐⭐⭐⭐⭐ | ⭐⭐ | 一時的な作業・学習中 |
| .env ファイル | ⭐⭐⭐⭐ | ⭐⭐⭐⭐ | プロジェクト作業 |
| PowerShell プロファイル | ⭐⭐ | ⭐⭐⭐⭐⭐ | 個人環境（要注意） |

### 方法1: セッション単位（一時的）

PowerShell起動ごとに手動設定する方法です。最も安全ですが、毎回設定が必要です。

```powershell
# PowerShell 起動後に毎回実行
$env:AZURE_DEVOPS_EXT_PAT = "your-azure-devops-pat-token"
$env:AZURE_DEVOPS_ORG = "https://dev.azure.com/bell999"
$env:AZURE_DEVOPS_PROJECT = "az400-handson3"

# 設定後、コマンド実行可能
az devops configure --defaults organization=https://dev.azure.com/bell999
az devops project list
```

### 方法2: .env ファイル（推奨）

プロジェクトルートに `.env` ファイルを作成し、`.gitignore` でバージョン管理から除外します。

**⚠️ 注意**: PAT の値は「🔑 認証情報の設定」セクションで作成した**トークンの値**（52文字程度の長い文字列）を使用してください。Token名（`az400-handson3`）ではありません。

```powershell
# .env ファイルを作成
@"
AZURE_DEVOPS_EXT_PAT=your-actual-pat-token-value-here
AZURE_DEVOPS_ORG=https://dev.azure.com/bell999
AZURE_DEVOPS_PROJECT=az400-handson3
"@ | Out-File -FilePath .env -Encoding utf8

# .gitignore に追加（重要！GitにPATをコミットしない）
if (!(Test-Path .gitignore)) {
    New-Item -ItemType File -Path .gitignore
}
".env" | Out-File -Append -FilePath .gitignore -Encoding utf8

# .env ファイルから環境変数を読み込む
Get-Content .env | ForEach-Object {
    if ($_ -match '^([^=]+)=(.*)$') {
        Set-Item -Path "env:$($matches[1])" -Value $matches[2]
    }
}

# 読み込みを確認
echo $env:AZURE_DEVOPS_EXT_PAT
```

**💡 便利なヘルパー関数**

PowerShell プロファイルに追加すると、毎回 `.env` を簡単に読み込めます：

```powershell
# 関数を定義（$PROFILE に追加推奨）
function Load-DotEnv {
    if (Test-Path .env) {
        Get-Content .env | ForEach-Object {
            if ($_ -match '^([^=]+)=(.*)$') {
                Set-Item -Path "env:$($matches[1])" -Value $matches[2]
            }
        }
        Write-Host "✅ .env ファイルを読み込みました" -ForegroundColor Green
    } else {
        Write-Host "❌ .env ファイルが見つかりません" -ForegroundColor Red
    }
}

# 使用方法
Load-DotEnv
```

### 方法4: Azure Key Vault（最も推奨）

Azure Key Vault を使用すると、PAT を最も安全に管理できます。

**⚠️ 前提条件**:
- Azure CLI でログイン済み（`az login`）
- Azure サブスクリプションが有効

#### Step 1: リソースグループと Key Vault を作成

```powershell
# 1. リソースグループを作成（存在しない場合）
az group create `
  --name "rg-az400-handson3" `
  --location "japaneast"

# 2. 一意な Key Vault 名を生成
# Key Vault 名はグローバルに一意である必要があるため、ユーザー名を含める
$kvName = "kv-az400-$($env:USERNAME)"
Write-Host "Key Vault name: $kvName"

# 3. Key Vault を作成
az keyvault create `
  --name $kvName `
  --resource-group "rg-az400-handson3" `
  --location "japaneast" `
  --enable-rbac-authorization true

# 4. 自分に Key Vault Secrets Officer 権限を付与
$userId = az ad signed-in-user show --query id -o tsv
$subscriptionId = az account show --query id -o tsv

az role assignment create `
  --role "Key Vault Secrets Officer" `
  --assignee $userId `
  --scope "/subscriptions/$subscriptionId/resourceGroups/rg-az400-handson3/providers/Microsoft.KeyVault/vaults/$kvName"

# 権限の伝播を待つ（30秒程度）
Write-Host "Waiting for RBAC propagation..."
Start-Sleep -Seconds 30
```

#### Step 2: Azure DevOps PAT を Key Vault に保存

```powershell
# PAT を一時的に環境変数にセット
$env:AZURE_DEVOPS_EXT_PAT = "your-actual-pat-token-value-here"

# Key Vault に保存
az keyvault secret set `
  --vault-name $kvName `
  --name "AZURE-DEVOPS-PAT" `
  --value $env:AZURE_DEVOPS_EXT_PAT

Write-Host "✅ Azure DevOps PAT saved to Key Vault: $kvName"
```

#### Step 3: Key Vault から PAT を取得して使用

```powershell
# Key Vault から PAT を取得して環境変数にセット
$env:AZURE_DEVOPS_EXT_PAT = az keyvault secret show `
  --vault-name $kvName `
  --name "AZURE-DEVOPS-PAT" `
  --query value -o tsv

# Azure DevOps の既定の Organization を設定
az devops configure --defaults organization=https://dev.azure.com/bell999

# プロジェクト一覧を表示（動作確認）
az devops project list --output table

# セッション終了時にクリア（オプション）
Remove-Item Env:\AZURE_DEVOPS_EXT_PAT
```

#### 💡 Key Vault を使うメリット

- 🔒 **最高レベルのセキュリティ**: PAT を平文ファイルに保存する必要がない
- 🔒 **アクセス制御**: Azure RBAC で誰がアクセスできるか管理可能
- 🔒 **監査ログ**: 誰がいつアクセスしたか記録される
- 🔒 **自動ローテーション**: 有効期限管理とトークン更新が可能
- 🔒 **チーム共有**: チームメンバーと安全に共有できる
- 🔒 **バックアップ**: Azure が自動でバックアップを管理

#### 📝 便利なヘルパー関数

PowerShell プロファイル（`$PROFILE`）に追加すると、毎回簡単に取得できます：

```powershell
# 関数を定義（$PROFILE に追加推奨）
function Load-AzureDevOpsPAT {
    param(
        [string]$KeyVaultName = "kv-az400-$($env:USERNAME)"
    )
    
    $env:AZURE_DEVOPS_EXT_PAT = az keyvault secret show `
        --vault-name $KeyVaultName `
        --name "AZURE-DEVOPS-PAT" `
        --query value -o tsv
    
    if ($env:AZURE_DEVOPS_EXT_PAT) {
        Write-Host "✅ Azure DevOps PAT loaded from Key Vault: $KeyVaultName" -ForegroundColor Green
    } else {
        Write-Host "❌ Failed to load PAT from Key Vault" -ForegroundColor Red
    }
}

# 使用方法
Load-AzureDevOpsPAT
```

### Key Vault へのアクセスエラー

**症状**: `az keyvault secret show` で "Forbidden" または "Access denied" エラー

```powershell
# 1. 自分のロール割り当てを確認
$kvName = "kv-az400-$($env:USERNAME)"
$subscriptionId = az account show --query id -o tsv
$kvResourceId = "/subscriptions/$subscriptionId/resourceGroups/rg-az400-handson3/providers/Microsoft.KeyVault/vaults/$kvName"

az role assignment list --scope $kvResourceId --assignee (az ad signed-in-user show --query id -o tsv) --output table

# 2. ロールが割り当てられていない場合は再度割り当て
az role assignment create `
  --role "Key Vault Secrets Officer" `
  --assignee (az ad signed-in-user show --query id -o tsv) `
  --scope $kvResourceId

# 3. RBAC の伝播を待つ（最大5分）
Start-Sleep -Seconds 30
```

**症状**: Key Vault 名が重複してエラー

```powershell
# 一意な Key Vault 名を生成（ランダムサフィックス付き）
$randomSuffix = -join ((65..90) + (97..122) | Get-Random -Count 4 | ForEach-Object {[char]$_})
$kvName = "kv-az400-$($env:USERNAME)-$randomSuffix"
Write-Host "New Key Vault name: $kvName"

# 名前の可用性を確認
az keyvault show --name $kvName 2>$null
if ($LASTEXITCODE -eq 0) {
    Write-Host "❌ Key Vault already exists" -ForegroundColor Red
} else {
    Write-Host "✅ Key Vault name is available" -ForegroundColor Green
}
```
