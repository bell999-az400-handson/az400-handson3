# Lab 4: セキュリティとコンプライアンス

## 🎯 目的
このLabでは、Azure DevOps と Azure のセキュリティ機能を学び、Service Principal 認証、Azure AD PIM、Branch Policy による品質ゲートを実装します。

## ⏱️ 所要時間
約60分

- Lab 0 の環境準備が完了していること
- Azure サブスクリプション

## 🎓 学習内容

### 重要ポイント（試験頻出）
✅ **Service Principal 認証に必要な3つの値**
- Application ID (Client ID)
- Client Secret
- Tenant ID
- ❌ Object ID は不要
- ❌ Subscription ID も不要（接続には不要）

✅ **Azure AD PIM (Privileged Identity Management)**
- Azure AD Premium P2 ライセンスが必須
- Just-in-Time (JIT) アクセス
- 承認ベースのアクセス
- 時間制限付きアクセス

## 📝 演習内容

### Exercise 1: Service Principal の作成

#### 1.1 Azure AD アプリケーションの登録

```powershell
# Azure CLI で Service Principal を作成
az ad sp create-for-rbac `
  --name "az400-handson-sp" `
  --role contributor `
  --scopes /subscriptions/{subscription-id}

# 出力例:
# {
#   "appId": "12345678-1234-1234-1234-123456789abc",          # Application ID
#   "displayName": "az400-handson-sp",
#   "password": "abc123~secret~xyz789",                       # Client Secret
#   "tenant": "87654321-4321-4321-4321-cba987654321"         # Tenant ID
# }
```

#### 1.2 重要な値の保存

**必要な3つの値（試験重要）:**

| 値 | JSON キー | 用途 |
|-----|-----------|------|
| Application ID | `appId` | アプリケーションの識別子 |
| Client Secret | `password` | 認証用のシークレット |
| Tenant ID | `tenant` | Azure AD テナントの識別子 |

これらをメモ帳などに保存してください（Client Secret は再表示不可）。

#### 1.3 Azure Portal で確認

1. [Azure Portal](https://portal.azure.com/) にアクセス
2. 「Microsoft Entra ID」(旧 Azure AD) → 「App registrations」を開く
3. 「az400-handson-sp」を検索
4. 確認事項：
   - Application (client) ID
   - Directory (tenant) ID
   - Certificates & secrets で Client secret

### Exercise 2: Service Principal でログイン

#### 2.1 環境変数の設定

```powershell
# PowerShell で環境変数を設定
$env:AZURE_CLIENT_ID = "your-application-id"
$env:AZURE_CLIENT_SECRET = "your-client-secret"
$env:AZURE_TENANT_ID = "your-tenant-id"

# 確認
echo $env:AZURE_CLIENT_ID
echo $env:AZURE_TENANT_ID
```

#### 2.2 Service Principal でログイン

```powershell
# Service Principal でログイン
az login --service-principal `
  --username $env:AZURE_CLIENT_ID `
  --password $env:AZURE_CLIENT_SECRET `
  --tenant $env:AZURE_TENANT_ID

# ログインできたことを確認
az account show

# リソースグループ一覧を取得
az group list --output table
```

### Exercise 3: Azure DevOps Service Connection

#### 3.1 Service Connection の作成

1. Azure DevOps → Project Settings → Service connections
2. 「New service connection」をクリック
3. 「Azure Resource Manager」を選択 → Next
4. 「Service principal (manual)」を選択
5. 以下を入力：
   - Environment: Azure Cloud
   - Scope Level: Subscription
   - Subscription ID: {your-subscription-id}
   - Subscription Name: {your-subscription-name}
   - **Service Principal Id**: {Application ID}
   - **Service Principal Key**: {Client Secret}
   - **Tenant ID**: {Tenant ID}
   - Service connection name: `AzureServiceConnection`
6. 「Verify」をクリックして検証
7. ✅ Grant access permission to all pipelines にチェック
8. 「Verify and save」をクリック

#### 3.2 パイプラインで使用

`azure-pipelines-deploy.yml` を作成：

```yaml
# azure-pipelines-deploy.yml
trigger: none

pool:
  vmImage: 'ubuntu-latest'

variables:
  resourceGroupName: 'az400-handson-rg'
  location: 'japaneast'

stages:
- stage: Deploy
  jobs:
  - job: DeployJob
    steps:
    # Service Principal で Azure にログイン
    - task: AzureCLI@2
      displayName: 'Create Resource Group'
      inputs:
        azureSubscription: 'AzureServiceConnection'  # Service Connection 名
        scriptType: 'bash'
        scriptLocation: 'inlineScript'
        inlineScript: |
          echo "Logged in as:"
          az account show --query user.name -o tsv
          
          # リソースグループを作成
          az group create \
            --name $(resourceGroupName) \
            --location $(location)
          
          echo "Resource group created successfully"
```

### Exercise 4: Azure AD PIM の設定

#### 4.1 Premium P2 ライセンスの確認

1. Azure Portal → Microsoft Entra ID → Licenses → All products
2. 確認事項：
   - Azure AD Premium P2 があるか確認
   - ない場合は、Azure AD Premium P1 では PIM を使用できない

#### 4.2 PIM の機能（試験重要）

| 機能 | Premium P1 | Premium P2 |
|------|------------|------------|
| 条件付きアクセス | ✅ | ✅ |
| MFA | ✅ | ✅ |
| Privileged Identity Management | ❌ | ✅ |
| Just-in-Time アクセス | ❌ | ✅ |
| 承認ベースのロール割り当て | ❌ | ✅ |
| アクセスレビュー | 一部 | ✅ |

#### 4.3 PIM の有効化（P2 ライセンスがある場合）

1. Azure Portal → Microsoft Entra ID → Privileged Identity Management
2. 「Azure AD roles」をクリック
3. 「Settings」→ Role を選択（例: Contributor）
4. 「Edit」をクリック
5. 設定：
   - Activation maximum duration: 8 hours
   - ✅ Require approval to activate
   - ✅ Require justification on activation
   - ✅ Require multi-factor authentication on activation

### Exercise 5: Branch Policy による品質ゲート

#### 5.1 必須レビュアーの設定

1. Azure DevOps → Repos → Branches
2. `main` ブランチの「...」→「Branch policies」
3. 「Automatically included reviewers」セクション
4. 「+ Add automatic reviewers」をクリック
5. 設定：
   - Reviewers: 特定のユーザーまたはグループを選択
   - Path filters: `*` (すべてのファイル)
   - Policy requirement: Required

#### 5.2 Build Validation Policy

```yaml
# azure-pipelines-validation.yml
trigger: none

pr:
  branches:
    include:
    - main

pool:
  vmImage: 'ubuntu-latest'

steps:
- task: UseDotNet@2
  inputs:
    version: '8.0.x'

- script: dotnet build --configuration Release
  displayName: 'Build Solution'

- script: dotnet test --no-build --configuration Release
  displayName: 'Run Tests'

# セキュリティスキャン（例）
- script: |
    echo "Running security scan..."
    # 実際には OWASP Dependency Check などを実行
  displayName: 'Security Scan'
```

Branch Policy で設定：
1. Build Validation → 「+」をクリック
2. Build pipeline: `azure-pipelines-validation.yml`
3. Display name: `PR Validation`
4. Policy requirement: Required

#### 5.3 Status Policy（SonarCloud など）

SonarCloud 連携の例：

```yaml
# azure-pipelines-sonar.yml
trigger: none

pr:
  branches:
    include:
    - main

pool:
  vmImage: 'ubuntu-latest'

variables:
  sonarCloudOrganization: 'your-org'
  sonarCloudProjectKey: 'your-project-key'

steps:
# SonarCloud の準備
- task: SonarCloudPrepare@1
  inputs:
    SonarCloud: 'SonarCloudConnection'
    organization: '$(sonarCloudOrganization)'
    scannerMode: 'MSBuild'
    projectKey: '$(sonarCloudProjectKey)'
    projectName: 'AZ400-HandsOn'

# ビルド
- task: DotNetCoreCLI@2
  inputs:
    command: 'build'
    projects: '**/*.csproj'

# SonarCloud 解析
- task: SonarCloudAnalyze@1

# Quality Gate の確認
- task: SonarCloudPublish@1
  inputs:
    pollingTimeoutSec: '300'
```

Branch Policy で Status Check を追加：
1. Status checks → 「+ Add status policy」
2. Status to check: `SonarCloud/quality gate`
3. Policy requirement: Required

### Exercise 6: シークレット管理

#### 6.1 Azure Key Vault の作成

```powershell
# Key Vault を作成
az keyvault create `
  --name "az400-kv-$(Get-Random -Maximum 9999)" `
  --resource-group az400-handson-rg `
  --location japaneast

# Key Vault 名を変数に保存
$keyVaultName = "az400-kv-1234"  # 実際の名前に置き換え
```

#### 6.2 シークレットの保存

```powershell
# Client Secret を Key Vault に保存
az keyvault secret set `
  --vault-name $keyVaultName `
  --name "ServicePrincipalSecret" `
  --value "your-client-secret"

# 保存されたことを確認
az keyvault secret show `
  --vault-name $keyVaultName `
  --name "ServicePrincipalSecret" `
  --query "value" -o tsv
```

#### 6.3 パイプラインから Key Vault を使用

```yaml
# azure-pipelines-keyvault.yml
trigger: none

pool:
  vmImage: 'ubuntu-latest'

variables:
- group: KeyVaultSecrets  # Variable Group（後で作成）

steps:
# Key Vault からシークレットを取得
- task: AzureKeyVault@2
  inputs:
    azureSubscription: 'AzureServiceConnection'
    KeyVaultName: 'az400-kv-1234'
    SecretsFilter: '*'
    RunAsPreJob: true

# シークレットを使用（例）
- script: |
    echo "Using secret from Key Vault"
    # $(ServicePrincipalSecret) として参照可能
  displayName: 'Use Secret'
  env:
    SECRET: $(ServicePrincipalSecret)
```

#### 6.4 Variable Group の作成

1. Azure DevOps → Pipelines → Library
2. 「+ Variable group」をクリック
3. Variable group name: `KeyVaultSecrets`
4. ✅ Link secrets from an Azure key vault as variables
5. Azure subscription: `AzureServiceConnection`
6. Key vault name: `az400-kv-1234`
7. 「Authorize」をクリック
8. Secrets を選択（ServicePrincipalSecret）
9. 「Save」をクリック

### Exercise 7: Managed Identity の使用

#### 7.1 User-Assigned Managed Identity の作成

```powershell
# Managed Identity を作成
az identity create `
  --name "az400-mi" `
  --resource-group az400-handson-rg `
  --location japaneast

# Principal ID を取得
$principalId = az identity show `
  --name "az400-mi" `
  --resource-group az400-handson-rg `
  --query "principalId" -o tsv

echo "Principal ID: $principalId"
```

#### 7.2 Key Vault へのアクセス権限を付与

```powershell
# Managed Identity に Key Vault の読み取り権限を付与
az keyvault set-policy `
  --name $keyVaultName `
  --object-id $principalId `
  --secret-permissions get list
```

### Exercise 8: コンプライアンスチェック

#### 8.1 Azure Policy の確認

```powershell
# サブスクリプションの Policy 一覧
az policy assignment list `
  --resource-group az400-handson-rg `
  --output table

# 特定の Policy の詳細
az policy state list `
  --resource-group az400-handson-rg `
  --filter "ComplianceState eq 'NonCompliant'" `
  --output table
```

#### 8.2 パイプラインでのコンプライアンスチェック

```yaml
# azure-pipelines-compliance.yml
trigger: none

pool:
  vmImage: 'ubuntu-latest'

steps:
# ARM テンプレートの検証
- task: AzureResourceManagerTemplateDeployment@3
  inputs:
    deploymentScope: 'Resource Group'
    azureResourceManagerConnection: 'AzureServiceConnection'
    subscriptionId: '{subscription-id}'
    action: 'Create Or Update Resource Group'
    resourceGroupName: 'az400-handson-rg'
    location: 'Japan East'
    templateLocation: 'Linked artifact'
    csmFile: 'template.json'
    deploymentMode: 'Validation'  # 検証のみ

# セキュリティスキャン
- script: |
    echo "Running security compliance check..."
    # 実際には Azure Security Center の結果を確認
  displayName: 'Security Compliance Check'
```

## ✅ 確認問題

### Q1: Service Principal 認証に必要な値を3つ選んでください
- [ ] A. Application ID
- [ ] B. Object ID
- [ ] C. Client Secret
- [ ] D. Tenant ID
- [ ] E. Subscription ID

<details>
<summary>解答</summary>

**正解: A, C, D**

説明:
- Application ID: アプリケーションの識別子
- Client Secret: 認証用のシークレット
- Tenant ID: Azure AD テナントの識別子
- Object ID と Subscription ID は接続には不要
</details>

### Q2: Azure AD PIM に必要なライセンスは？
- [ ] A. Azure AD Free
- [ ] B. Azure AD Premium P1
- [ ] C. Azure AD Premium P2
- [ ] D. Microsoft 365 E3

<details>
<summary>解答</summary>

**正解: C**

説明:
- Privileged Identity Management (PIM) は Azure AD Premium P2 ライセンスが必須
- P1 では使用できない
</details>

### Q3: Branch Policy で SonarCloud の Quality Gate を強制するために使用するポリシーは？
- [ ] A. Build Validation
- [ ] B. Status Policy
- [ ] C. Required reviewers
- [ ] D. Comment resolution

<details>
<summary>解答</summary>

**正解: B**

説明:
- Status Policy: 外部サービス（SonarCloud など）の品質チェックを強制
- Build Validation: Azure Pipelines のビルドを強制
</details>
