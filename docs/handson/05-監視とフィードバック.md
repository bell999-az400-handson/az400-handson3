# Lab 5: 監視とフィードバック

## 🎯 目的
このLabでは、Azure Monitor、Application Insights、Logic App による通知、Azure DevOps ダッシュボードを使用した監視とフィードバックループを実装します。

## ⏱️ 所要時間
約60分

## 📋 前提条件
- Lab 0 の環境準備が完了していること
- Azure サブスクリプション
- Azure DevOps プロジェクト

## 🎓 学習内容

### 重要ポイント（試験頻出）
✅ **Azure Monitor メトリクスの種類**
- Lead Time: 要求から完了までの総時間（MTTR: 平均復旧時間）
- Cycle Time: 作業開始から完了までの時間
- Velocity: スプリントで完了したバックログ数

✅ **Azure Monitor 通知**
- Action Group で通知先を管理
- Logic App で Teams などに通知

✅ **Dependency Agent**
- Service Map には Dependency Agent が必須
- Azure Monitor Agent (AMA) では代替不可

#### 1.5 カスタムテレメトリの追加

新しいコントローラーを作成 `Controllers/MetricsController.cs`:

```csharp
using Microsoft.ApplicationInsights;
using Microsoft.ApplicationInsights.DataContracts;
using Microsoft.AspNetCore.Mvc;

namespace WebApp.Controllers;

[ApiController]
[Route("api/[controller]")]
public class MetricsController : ControllerBase
{
    private readonly TelemetryClient _telemetryClient;
    private readonly ILogger<MetricsController> _logger;

    public MetricsController(TelemetryClient telemetryClient, ILogger<MetricsController> logger)
    {
        _telemetryClient = telemetryClient;
        _logger = logger;
    }

    [HttpGet("track")]
    public IActionResult TrackMetric()
    {
        // カスタムメトリクスを送信
        _telemetryClient.TrackMetric("CustomMetric", 42);
        
        // カスタムイベントを送信
        _telemetryClient.TrackEvent("CustomEvent", new Dictionary<string, string>
        {
            { "User", "TestUser" },
            { "Action", "MetricTracked" }
        });

        _logger.LogInformation("Metric tracked successfully");
        
        return Ok("Metric tracked");
    }

    [HttpGet("exception")]
    public IActionResult TrackException()
    {
        try
        {
            throw new InvalidOperationException("Test exception for Application Insights");
        }
        catch (Exception ex)
        {
            _telemetryClient.TrackException(ex);
            _logger.LogError(ex, "Exception tracked");
            return StatusCode(500, "Exception tracked");
        }
    }
}
```

#### 2.2 Kusto クエリの例（KQL）

Application Insights のログを分析：

```kql
// 過去24時間のリクエスト数
requests
| where timestamp > ago(24h)
| summarize RequestCount = count() by bin(timestamp, 1h)
| render timechart

// 失敗したリクエスト
requests
| where success == false
| where timestamp > ago(24h)
| project timestamp, name, resultCode, duration
| order by timestamp desc

// 例外の集計
exceptions
| where timestamp > ago(24h)
| summarize ExceptionCount = count() by type, outerMessage
| order by ExceptionCount desc

// カスタムメトリクス
customMetrics
| where name == "CustomMetric"
| where timestamp > ago(24h)
| summarize avg(value) by bin(timestamp, 5m)
| render timechart
```

### Exercise 4: アラートルールの作成

#### 4.1 メトリックアラートの作成

```powershell
# Application Insights の失敗率アラート
az monitor metrics alert create `
  --name "HighFailureRate" `
  --resource-group az400-handson-rg `
  --scopes "/subscriptions/{subscription-id}/resourceGroups/az400-handson-rg/providers/microsoft.insights/components/az400-appinsights" `
  --condition "avg requests/failed > 5" `
  --window-size 5m `
  --evaluation-frequency 1m `
  --action az400-action-group `
  --description "Alert when request failure rate exceeds 5%"
```

#### 4.2 ログアラートの作成

1. Azure Portal → Monitor → Alerts → Create alert rule
2. Scope: Application Insights リソースを選択
3. Condition:
   - Signal: Custom log search
   - KQL クエリ:
   ```kql
   exceptions
   | where timestamp > ago(5m)
   | summarize count() by type
   | where count_ > 10
   ```
   - Alert logic:
     - Threshold: 0
     - Aggregation: Count
4. Actions: `az400-action-group` を選択
5. Details:
   - Severity: 2 - Warning
   - Alert rule name: `HighExceptionRate`

### Exercise 5: Dependency Agent と Service Map

#### 5.1 仮想マシンの作成（デモ用）

```powershell
# VM を作成
az vm create `
  --resource-group az400-handson-rg `
  --name az400-vm `
  --image Ubuntu2204 `
  --size Standard_B2s `
  --admin-username azureuser `
  --generate-ssh-keys `
  --public-ip-address-allocation static
```

#### 5.2 Azure Monitor Agent のインストール

```powershell
# Azure Monitor Agent 拡張機能をインストール
az vm extension set `
  --resource-group az400-handson-rg `
  --vm-name az400-vm `
  --name AzureMonitorLinuxAgent `
  --publisher Microsoft.Azure.Monitor `
  --enable-auto-upgrade true
```

#### 5.3 Dependency Agent のインストール（Service Map 用）

```powershell
# Dependency Agent をインストール
az vm extension set `
  --resource-group az400-handson-rg `
  --vm-name az400-vm `
  --name DependencyAgentLinux `
  --publisher Microsoft.Azure.Monitoring.DependencyAgent
```

#### 5.4 Service Map の確認

1. Azure Portal → Monitor → Insights → Virtual Machines
2. VM を選択
3. 「Map」タブを開く
4. ✅ Dependency Agent がインストールされていると依存関係が表示される

#### 重要ポイント（試験頻出）
- Service Map には **Dependency Agent が必須**
- Azure Monitor Agent (AMA) だけでは Service Map は動作しない
- Dependency Agent は依存関係とプロセス間通信を可視化

### Exercise 6: Azure DevOps ダッシュボード

#### 6.1 Lead Time / Cycle Time / Velocity の理解

| メトリクス | 定義 | 用途 | 計算期間 |
|------------|------|------|----------|
| **Lead Time** | 要求から完了までの総時間 | 顧客への応答性・MTTR | バックログ作成～完了 |
| **Cycle Time** | 作業開始から完了までの時間 | チームの効率性 | Active～完了 |
| **Velocity** | スプリントで完了したポイント数 | 生産性・計画精度 | スプリント単位 |

#### 6.2 Lead Time for Changes のダッシュボード作成

1. Azure DevOps → Overview → Dashboards
2. 「+ New Dashboard」をクリック
3. Name: `AZ400 Metrics Dashboard`
4. 「+ Add Widget」をクリック
5. 「Lead Time」ウィジェットを追加
   - Team: 自分のチーム
   - Backlog level: User Stories
   - Time period: Last 30 days
6. 配置して「Done Editing」

#### 6.3 Cycle Time ウィジェットの追加

1. 「Edit」をクリック
2. 「+ Add Widget」→「Cycle Time」を追加
3. 設定:
   - Rolling period: 30 days
   - Time period: Last 30 days
4. Lead Time の隣に配置

#### 6.4 Velocity ウィジェットの追加

1. 「+ Add Widget」→「Velocity」を追加
2. 設定:
   - Team: 自分のチーム
   - Iterations: Last 6 iterations
   - Work items: User Stories

#### 6.5 試験対策ポイント

**Q: 復旧までの平均時間（MTTR）を測定するメトリクスは？**
- **A: Lead Time**
- Bug が報告されてから修正完了までの時間を測定

**Q: 完了したバックログの数を確認するウィジェットは？**
- **A: Velocity**
- スプリントごとの完了ポイント数を表示

## 📊 演習のまとめ

### Azure Monitor 通知フロー

```
Application Insights
    ↓
Alert Rule (メトリクス/ログ)
    ↓
Action Group
    ↓
Logic App (HTTP Trigger)
    ↓
Microsoft Teams 通知
```

### メトリクスの使い分け

| シナリオ | 使用するメトリクス |
|----------|-------------------|
| 顧客への応答時間を測定 | Lead Time |
| チームの作業効率を測定 | Cycle Time |
| スプリント計画の精度向上 | Velocity |
| システム復旧時間（MTTR） | Lead Time |

## ✅ 確認問題

### Q1: Azure Service Map に必要なエージェントは？
- [ ] A. Azure Monitor Agent のみ
- [ ] B. Dependency Agent のみ
